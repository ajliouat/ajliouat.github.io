Separate failure sources

A manipulation instruction passes through several decisions: what action is intended, which object is referenced, how a target is represented and whether the controller can reach it. Separate interfaces make those failures easier to investigate. They do not establish that a complete language-to-action system has been learned.

What the current test pipeline executes

flowchart TB Instruction["Instruction"] --> Mock["MockVLM keyword planner"] Mock --> Parser["Validated task sequence"] Scene["Privileged simulator state"] --> Ground["SimGrounder"] Parser --> Ground Ground --> Exec["Hierarchical executor + scripted policies"] Exec --> Env["MuJoCo tabletop"] Env --> Scene Future["Real VLM, visual grounding and learned control: separate validation"]

The inexpensive test path uses MockVLM keyword matching, SimGrounder’s privileged scene state and scripted control. A Transformers-backed planner and SAC training code are separate extensions. The existing mock tests cannot measure real VLM accuracy or image-based grounding.

Environment and task semantics

The environment uses a custom Franka-inspired seven-joint arm, randomized tabletop objects, delta end-effector actions and a bounded episode length. It is a simulation testbed, not evidence of transfer to a calibrated physical robot.

Each task needs an explicit success predicate. In particular, the language environment checks final scene conditions: a condition can already hold or be met by chance. Its random-policy success rate does not measure instruction understanding or intentional completion.

Planning and grounding evidence

MockVLM and SimGrounder help test parsing, aliases and data flow without model downloads. Their expected outputs are designed fixtures. Reporting those passes as “100% VLM accuracy” would confuse software checks with a held-out model evaluation.

The grounding module exposes the distinction between simulator-state matching and proposed visual grounding. A real perception study needs camera inputs, independently labeled targets and evaluation cases outside the planner’s hand-written rules.

Scripted control and learned policies

Scripted reaching and pick/place controllers provide diagnostic baselines. SAC training and checkpoint loading exist, but the historical baseline table contains random and scripted runs, not proof of a trained language-conditioned manipulation policy.

The reviewed executor supports move_to, pick and place; parser vocabulary does not establish additional executable motor skills. Its pick/place path also needs target-selection validation in multi-object scenes. Planning and control can both limit success.

The other archived random baselines—color pick, stacking and sorting—each report 0/100 successes. A dash or an absent run is not a zero result. Less-negative shaped return does not imply a multiplicative improvement or successful manipulation.

The original archive does not contain per-episode traces or complete environment/version provenance, and the evaluator did not seed the random action space. These records establish what was reported, not an exactly reproducible run or a learned-policy benchmark.

At zero successes in 100 trials, a Wilson interval is [0%, 3.70%]. Writing “0% ± 1.8%” incorrectly centers the interval on the observed proportion. Preserve lower and upper endpoints, and retain integer counts so a reader can recalculate them.

The next evidence should be reproducible

  • Seed both sources of randomness: resetting an environment with a seed does not automatically seed action_space.sample().
  • Retain individual outcomes: episode seeds, returns, lengths and success flags make aggregation inspectable.
  • Separate reward from success: a controller can improve shaped return while completing zero tasks. Ratios of negative returns are not meaningful success multipliers.
  • Validate one skill: first reproduce reaching, then test grasping with explicit target identity and bounded conditions before composing a language pipeline.

Future comparisons should record the source revision, dependency versions and checkpoint identity. No additional training run or new manipulation success result is asserted in this note.
